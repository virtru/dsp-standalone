Manual Setup

Overview

Runs the Virtru Data Security Platform (DSP) as a self-contained Docker Compose stack — no Kubernetes or bulk data ingestion. Intended to support local SDK development and testing.

Local dev only. This setup uses default usernames and credentials and should not be used for any purpose beyond local integration development and testing.

Architecture

Startup Dependency Chain

Docker Compose enforces this dependency order automatically:

1
keycloak-db starts and becomes healthy (pg_isready)
2
keycloak starts, connects to keycloak-db at localhost:25434, becomes healthy
3
dsp-keycloak-provisioning runs once (provisions realm, clients, users), exits 0
4
dsp-db starts in parallel, becomes healthy (pg_isready)
5
dsp starts after keycloak healthy + provisioning completed + dsp-db healthy
6
dsp-provision-federal-policy runs once after dsp healthy, loads federal attribute policy, exits 0

Allow ~2–3 minutes on first run for Keycloak to initialize.

Networking Model

Keycloak and DSP use network_mode: host — they bind directly to host ports. keycloak-db and dsp-db use Docker's default bridge network with published ports (25434 and 35433). Host-networked services connect to the databases via localhost:<port>.

Docker Image Build

The dev.dsp.Dockerfile is a two-stage build:

  1. Prep stage (alpine) — installs CA certificates, copies TLS certs/keys, KAS keys, config files, and builds a merged CA bundle
  2. Final stage (from proprietary DSP image) — layers in curl (for healthchecks), keys, sample configs, and dsp.yaml

Build arg DSP_IMAGE controls the base DSP image (e.g., localhost:5000/virtru/data-security-platform:v2.7.4).

Quick Start (Automated)

Prerequisites

Docker Engine ≥ 24 with Docker Compose v2 must be installed before running the setup script. The script handles all other tool installation automatically.

macOS: OrbStack is the recommended Docker runtime. Install it and start it before proceeding. Docker Desktop, Rancher Desktop, and Colima also work — see Supported Platforms for caveats.

Installation and Startup

With Docker running, the setup script handles tool installation, key generation, Docker registry setup, stack startup, and validation in a single command:

# From the DSP-standalone/ directory:
./setup_and_validate.sh

What the script does

1
Detects your OS and runs the appropriate prereqs script (mac_prereqs.sh or ubuntu_prereqs.sh)
2
Verifies all required tools installed successfully
3
Generates all TLS certificates and keys in dsp-keys/ (skips files that already exist)
4
Starts or verifies the local Docker registry — prompts for your Virtru DSP bundle path if the image is not yet loaded
5
Starts the Docker Compose stack and waits for DSP to become healthy
6
Runs all validation checks and prints a pass/fail summary

Flags

FlagEffect
(none)Full run: prereqs → keys → build → stack → infra checks → SDK tests
--skip-prereqsSkip tool installation; still validates tools are present
--no-buildStart stack using cached images — skips docker compose build
--validate-onlyRun infra checks + SDK validation against an already-running stack
--sdk-onlyRun Go SDK tests only — skips setup and all infra checks

Common Combinations

# Full run (default)
./setup_and_validate.sh

# Validate a running stack
./setup_and_validate.sh --validate-only

# Run only the Go SDK tests (fastest)
./setup_and_validate.sh --sdk-only

# Skip prereqs and skip rebuild (fastest repeat run)
./setup_and_validate.sh --skip-prereqs --no-build
Linux note: After running the prereqs script for the first time, Docker group membership requires a logout/login (or newgrp docker) before Docker commands work without sudo. Re-run with --skip-prereqs after logging back in.

Troubleshooting

▶ Keycloak Fails to Start
  • Verify dsp-keys/local-dsp.virtru.com.pem and .key.pem exist and are readable
  • Check Keycloak-DB is healthy: docker compose ps keycloak-db
  • Check Keycloak logs: docker logs virtru-dsp-only-keycloak-1

Linux — TLS Key Permissions

mkcert generates private keys with 0600. Keycloak runs as UID 1000 and cannot read root-owned 0600 files through a bind mount.

chmod 0644 dsp-keys/local-dsp.virtru.com.key.pem
docker compose restart keycloak

Linux — firewalld Blocking DB Port

Keycloak (host network) connects to keycloak-db (bridge) at localhost:25434. Firewalld can block this.

sudo firewall-cmd --permanent --zone=trusted --add-interface=docker0
sudo firewall-cmd --reload
docker compose restart keycloak

CentOS/RHEL — nftables/iptables Conflict

sudo update-alternatives --set iptables /usr/sbin/iptables-legacy
sudo update-alternatives --set ip6tables /usr/sbin/ip6tables-legacy
sudo systemctl restart docker
docker compose up -d
▶ DSP Fails to Start or Stays Unhealthy
  • Confirm local-dsp.virtru.com resolves: ping local-dsp.virtru.com
  • Confirm all KAS key files exist in dsp-keys/
  • Check DSP logs: docker logs virtru-dsp-only-dsp-1

Linux — KAS Key Permissions

chmod 0644 dsp-keys/kas-private.pem dsp-keys/kas-ec-private.pem dsp-keys/policyimportexport/cosign.key
docker compose restart dsp
Local dev only. Setting private keys to 0644 is safe for local development only. Do not use in production.
▶ Provisioning Container Exits Non-Zero
# Check logs
docker compose logs dsp-keycloak-provisioning

# Re-run provisioning manually
docker compose run --rm dsp-keycloak-provisioning

# Re-run federal policy provisioning
docker compose run --rm dsp-provision-federal-policy
▶ Port Conflicts

If any port is already in use, stop the conflicting process or override the published port in the compose file.

# Example: identify what's using port 5000
lsof -i :5000
▶ Linux — Docker Build DNS Failures

Containers cannot resolve external DNS. Configure Docker's DNS:

echo '{"dns": ["8.8.8.8", "1.1.1.1"]}' | sudo tee /etc/docker/daemon.json
sudo systemctl restart docker

Three Go programs test the full TDF encrypt/decrypt flow. Run them individually or all together via the setup script:

▶ toySDK.go — Encrypt/Decrypt Round-Trip Smoke Test

Authenticates as Alex (aaa@topsecret.usa, TS/USA), encrypts plaintext into a TDF with classification/topsecret, relto/usa, relto/fvey, then decrypts it. Prints plaintext, hex dump of encrypted content, Shannon entropy, and decrypted output.

# Run directly
go run toySDK.go

# Or build first
go build -o toySDK toySDK.go && ./toySDK

▶ bobTestAlexFile.go — Cross-User Decryption FVEY Test

Bob (bbb@topsecret.gbr, TS/GBR) decrypts Alex's TDF. Bob can decrypt because:

  • classification/topsecret — Bob holds TS clearance
  • relto/fvey — GBR is a Five Eyes member (ANY_OF rule, one match is enough)
# Run toySDK.go first to create alex_test.tdf
go run toySDK.go
go run bobTestAlexFile.go

Failure Cases

Could not open alex_test.tdftoySDK.go has not been run yet

▶ aliceTestAlexFile.go — Access Denial Test Policy Test

Alice (aaa@secret.usa, S/USA) attempts to decrypt Alex's TDF. Access is correctly denied because:

  • classification/topsecret — Alice only holds Secret (S) clearance
  • HIERARCHY rule: Secret < Top Secret, so Alice cannot access Top Secret data
SUCCESS = access denied. This test reports SUCCESS when access is correctly denied. If Alice decrypts the file, the test reports FAILURE (policy misconfiguration).

Access Control (ABAC)

DSP uses Attribute-Based Access Control (ABAC). The flow from user identity to data access:

1
Keycloak user has IdP attributes (clearance, needToKnow, nationality)
2
Subject Condition Sets in sample.federal_policy.yaml match those attributes
3
Subject Mappings link condition sets to DSP Attribute Values
4
Attribute values are applied to TDF-protected data at encrypt time
5
On decrypt, DSP checks whether the user's attributes satisfy all values on the data

Attribute Definitions

All attributes belong to the demo.com namespace and are defined in sample.federal_policy.yaml.

▶ classification — HIERARCHY rule Ordered

Values are ordered from highest to lowest. A user entitled to a higher level is automatically entitled to all lower levels.

ValueMeaning
topsecretTop Secret
secretSecret
confidentialConfidential
unclassifiedUnclassified

Keycloak clearance mappings

Keycloak clearance value(s)Entitled to
TS, Top Secret, topsecret, DV, PV, NV2topsecret (and all below)
S, SC, Secret, NV1secret (and all below)
C, Confidentialconfidential (and below)
U, Unclassifiedunclassified
▶ needtoknow — ALL_OF rule All Required

A user must hold all needtoknow values applied to a piece of data to decrypt it.

▶ relto — ANY_OF rule Any Match

A user needs at least one matching relto value. Includes coalition groups and individual ISO 3166-1 alpha-3 country codes.

▶ Step 4: Generate TLS Certificates and Keys
# 1. Install mkcert
# macOS:
brew install mkcert && mkcert -install

# 2. TLS certificate for Keycloak and DSP
mkcert \
  -cert-file dsp-keys/local-dsp.virtru.com.pem \
  -key-file  dsp-keys/local-dsp.virtru.com.key.pem \
  local-dsp.virtru.com "*.local-dsp.virtru.com" localhost

# 3. KAS RSA key pair
openssl req -x509 -nodes -newkey RSA:2048 -subj "/CN=kas" \
  -keyout dsp-keys/kas-private.pem -out dsp-keys/kas-cert.pem -days 365

# 4. KAS EC key pair
openssl ecparam -name prime256v1 > dsp-keys/ecparams.tmp
openssl req -x509 -nodes -newkey ec:dsp-keys/ecparams.tmp -subj "/CN=kas" \
  -keyout dsp-keys/kas-ec-private.pem -out dsp-keys/kas-ec-cert.pem -days 365
rm dsp-keys/ecparams.tmp

# 5. Policy import/export signing keys
# macOS:
brew install cosign

mkdir -p dsp-keys/policyimportexport
COSIGN_PASSWORD=changeme cosign generate-key-pair \
  --output-key-prefix dsp-keys/policyimportexport/cosign
printf '%s' 'changeme' > dsp-keys/policyimportexport/cosign.pass

# 6. Encrypted search key (placeholder)
printf '%s' '49e9a28af998c2678e6651ad4e60a2dbba2f3d284f58b224b3382919c1de7d55' \
  > dsp-keys/encrypted-search.key

On repeat runs where images are already built:

docker compose up -d
▶ Step 7: Stop / Restart / Logs
# Stop
docker compose down

# Stop and delete Postgres volumes
docker compose down -v

# View all logs
docker compose logs -f

# Single service logs
docker compose logs -f dsp
docker compose logs -f keycloak
OrbStack tip: Once the stack has been started successfully, you can manage it from the OrbStack UI — find the virtru-dsp-only container group and use play/stop buttons.
